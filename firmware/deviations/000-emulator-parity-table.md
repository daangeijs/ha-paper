# UI runtime and core vs the emulator

| Area | Emulator | Firmware | Why |
|---|---|---|---|
| Region signature | `JSON.stringify(vm)` per region | text record of every draw op of the region (`Canvas` record mode) | Same rule ("compare what is shown"), but exact for what is drawn; touch targets are collected in the same pass. |
| Page turn inside one screen (list parts) | always a partial refresh of `page` | region diff: only changed rows/headers are redrawn; a turn that changes nothing (single-page app) causes no refresh | Fewer redraws. |
| Region set changed during a commit | n/a | removed regions are cleared and included in the partial window | Needed for list rows that disappear. |
| Boot → setup decision | `!wifi.connected` → Wi-Fi setup | Wi-Fi setup only when no network is saved (`NotConfigured`, `SoftAP`, `WrongPassword`); a saved network still connecting goes to the dashboard with the offline icon | On hardware Wi-Fi is rarely up 1.6 s after boot. |
| Wi-Fi comes up while never linked | only via the setup flow | entering "Finish in your browser" whenever Wi-Fi transitions to connected and HA was never linked | Same outcome for a fresh device; covers reconnects. |
| Saved secure network tapped | `wifiConnect(ssid, '')` then refused ("At least 8 characters") | connects with the stored credentials (`Services::wifiConnect(ssid, "")`) | Emulator bug. |
| Settings › Wi-Fi "Disconnect" | `connected: null`, offline | `Services::wifiDisconnect()`: link dropped, credentials stay saved, no auto-reconnect until a network is picked (`wifiForget(ssid)` deletes them; not on the panel) | Same outcome; a saved network must not silently come back. |
| Settings › HA "Reconnect" / "Unlink" | local state | `Services::haReconnect()` (WebSocket reconnect now, backoff reset, fresh access token) / `Services::haUnlink()` (= `DELETE /api/v1/ha`: revoke at HA, delete the key, end console sessions); no confirm step, like the emulator | Real link. |
| "Simulate phone" buttons | emulator-only | Home link card button "Show the big code" opens Settings › Home Assistant link view; link stages show 1–2 from `HaState::Linking` | Real flow happens in the phone browser. |
| `[QR CODE]` placeholders | dashed boxes | real QR codes (ricmoo/QRCode): `http://<ip>` and `http://<ip>/link?p=CODE` (the hostname when there is no IP), Wi-Fi QR for `HA-Paper-Setup` | Placeholders in the design. |
| Hostname | `ha-paper.local` everywhere | `ha-paper-XXXX.local`, XXXX = last 4 hex digits of the Wi-Fi MAC (`net/wifi_mgr.h` `hostname()`): DHCP name and mDNS. On-screen text shows both, `ha-paper-XXXX.local or <ip>`; QR codes carry the IP, because phones (Android especially) often can't resolve `.local` and the screen is redrawn from live status. Nothing requires the name: OAuth client_id/redirect_uri follow the Host header, and the contract suite starts sign-in under both. `hostname` in `/status` and `/console/state`. The emulator uses the fixed fake `ha-paper-a1b2` (`emulator/src/core/data.ts` `HOST`), as do host renders | Two displays on one network both claimed `ha-paper.local`. |
| Console API hardening (issue #37) | `/console/state` returns the HA server/user to anyone; session writes checked only when an `Origin` is present | linked + no session → `home_assistant.server`/`.user`/`.discovered` empty. Cookie writes (non-GET, incl. `/ota/upload`) need `Origin` == `http://<Host>` or, without Origin, a Referer on that origin (`core/net_policy.h` `sameOriginWrite`), else 403. Bearer writes unchecked. HA token-endpoint failures log only the `error` field | LAN callers learned the HA URL and account; a missing Origin skipped the CSRF check. |
| Night face when booting at night | live values (`nightSnap` null) | snapshot captured on first draw ("Values as of HH:MM") | Same values, static. |
| Night window end (07:00) | React re-render, no logged refresh | explicit full refresh "night end" | The panel must be redrawn. |
| Idle back-to-Home during night | `goTo` + full refresh (draws the night face again) | silently resets the page, no refresh | Avoids a useless flash. |
| Taps on the standby face | ignored | ignored (parity; any key wakes) | — |
| Touch feedback | CSS `:active` | the action runs first; its own refresh is the feedback (a navigation's fast refresh, a partial that redraws the control). Only when it redraws nothing there (scene, script) is the control inverted, partially refreshed and restored (#212). Counted in `Stats::feedbackRefreshes`, and as partial activity for the scheduled clean (#26), but never forces a full itself. `App::setPressFeedback(false)` disables it (tests/renders) | SPEC §7 "pressed control inverts immediately". |
| Clean-up full refresh (#26) | handoff: a full after every `fullEvery` (8) partials | `RefreshPolicy` (`core/logic`): with the clock set, a partial never forces a full; at the first :00/:30 at least `cleanEvery` minutes (30 / 60 / 120, default 30) after the last full, the minute tick becomes one full refresh ("clean screen") if any partial (data, clock, tap feedback) was drawn since and night mode is not active (standby keeps it; night end is a full anyway). Slots are UTC-aligned epoch minutes (= local :00/:30 except in :45-offset zones). Clock unset (no SNTP): `kCleanCap` = 30 partials force a full ("ghosting limit"). New settings key `cleanEvery`; `fullEvery` is legacy (still validated, stored and served so a rolled-back firmware reads it; no effect). The screens.yaml tile key stays `fullEvery` ("Clean screen") and steps `cleanEvery`. Vectors: `spec/test-vectors/refresh.json` | Partials are B/W only since #38, so ghosting is the only reason to flash; 8 partials at 30 s polling flashed the panel every 2–4 min. New key instead of a migration: migrate.h forbids changing a key's meaning. |
| tado pending | cleared 900 ms after the (mock) call | cleared when HA reports `temperature` == sent value; dropped after 30 s without ack | Real acknowledgement. |
| Lights / away | state changes immediately in mock data | optimistic override until HA confirms (10 s timeout) | Real acknowledgement. |
| Status: "Sending" icon | any pending setpoint | shown from first tap until ack (also during the 1.5 s debounce) | Same as emulator. |
| About › Storage | "microSD 16 GB · 3% used" (mock) | "—" | Not provided by `Services`. |
| First-run screens (emulator DEVIATIONS 13, #23) | seeded on the first link without saved screens; no Settings tail (built in, #159) | same rules (`core/seed.cpp`, `spec/test-vectors/seed.json`); since #82 every stat / gauge entity is a sensor from the seed template answer (`live` = `EntityAdapter::sources()` only feeds the price tile and routes); no Settings tail: Settings is built in (#159) | Firmware has the full entity mapping. |
| Power saving (emulator DEVIATIONS 10) | Settings › Power (`powerSave` off/night/standby/glance, `wakeEvery`, `liveMin`), device state `asleep` | `net/power.cpp` runs `core/power` every second from the main loop and deep-sleeps (`X4Board::deepSleep`: panel deep-sleep command, front-light pads held LOW, `PowerManager::powerDownRailsForSleep`, GPIO1 latch held HIGH, ext1 wake GPIO3/GPIO7 any-low, ext0 wake GPIO21 STAT high, timer). The Power page is one of the built-in Settings pages, after Display style (#159). `/status` `power.mode` is `awake` or `glance` (a glance wake in progress); asleep it does not answer. Clock unknown (BM8563 never set, no NTP): local time is taken as 12:00, so no night window or 03:00 slot, only the relative timer | Hardware-only: currents, wake pins, latch, STAT polarity (#19, #20). |
| Glance (#10, default on battery per #18) | timer wake → fetch → redraw only on change, in-memory | timer wake (`esp_sleep_get_wakeup_cause`): no boot screen (`App::setPanelHeld`), Wi-Fi joins with the BSSID/channel cached in RTC memory and, while the DHCP lease we saw is < 1 h old, the cached IP (no scan, no DHCP; 8 s then a normal join, two failures drop the cache). The HA WebSocket runs as usual (auth → `subscribe_entities` filtered to the screens' entities, energy prefs, statistics): one TCP/TLS connection and one filtered snapshot, where REST `GET /api/states` returns every entity (hundreds of KB on a big install) and `/api/states/<id>` costs a round trip per entity. Settled = HA connected, data applied, 1.5 s without updates. Then `App::settle()` renders into the framebuffer only and the region signatures (minus clock regions `time`/`k<i>`) are hashed into a 48-entry snapshot in `RTC_NOINIT` (`core/glance.h` `Rtc`, magic ^ size + FNV-1a). `glance::step` decides; a redraw is one full refresh (the controller RAM is gone after deep sleep, no partial possible). Cap 20 s; HA unreachable → no redraw, wait doubles (30, 60, 120 min); the 3rd failure in a row draws the offline mark once. The HA access token is not kept in RTC memory: every wake exchanges the refresh token again (one extra HTTPS request; tokens stay out of RAM that survives resets) | A clock on the page can be up to 60 min behind: values unchanged for an hour redraw anyway (`stale`). |
| Live mode | key press within `liveMin` | the App's own key/touch events; a boot that is not a timer wake (power-on, Power/Right, charger) counts as one. Going to sleep from live: back to the home page in ambient chrome first (`App::prepareSleep`, one full refresh if anything differed), so the next wake compares like with like | — |
| First-boot safety (#10, council) | `armLeft` (0 in the emulator) | no deep sleep until this firmware version had 3 boots that ran 60 s with the network up (userdata `/arm.json` `{version, boots}`, ≤ 3 writes per version; never NVS); Right held during the first 3 s of a boot = live for 10 min; a USB host (HWCDC SOF) is external power. `GET /diagnostics` `deep_sleep {armed, boots_left}`; console "Glance armed after N more boots" | A display that never restarts stays live until it has been restarted twice more; a self-test sleep would arm it sooner (not built). |
| Deep-sleep wakes in the boot ring | device-sim: DEEPSLEEP boot per wake | a DEEPSLEEP boot right after a DEEPSLEEP boot replaces it (`core/diag` push; vectors), so 96 wakes a day never push a crash out of the 8 boots. DEEPSLEEP is not a crash reason: the crash-loop streak (#21) breaks on it. `/diag.json` is not rewritten per wake (30 min cadence) | Flash wear. |
| QEMU deep sleep | — | no deep sleep in QEMU: the RTC record gets a fake wake cause, the loop waits ≤ 8 s (a Power/Right key = button wake, `POST /__qemu/power?source=usb` = charger wake) and calls `esp_restart()`; diag records that reset as DEEPSLEEP. QEMU boots on "USB" (always live) until `POST /__qemu/power?source=battery[&armed=1]` (kept in RTC memory; also marks the API idle). `sim/qemu/glance-test.sh` (`make qemu-glance`) | QEMU has no RTC timer wake. |
| OTA "Checking GitHub…" state | local state | not shown (no checking state in `OtaState`) | Contract. |
| OTA steps text | timed mock steps | "Downloading firmware.bin" → "Checking SHA-256" / "Writing & setting boot partition" from `OtaState::Installing` | Driven by `NetStatus`. |
| OTA checks off in this build | GitHub check with mock releases | `X4_OTA_REPO` the `[YOU]/ha-paper` placeholder (`x4qemu` builds and forks; official `x4pro` builds check `daangeijs/ha-paper`, #217) → no GitHub check, no daily auto check, no night install. Settings › Updates: "Update checks off" + "Off in this build", no "Check for updates" button (`NetStatus::otaChecksOff`). `GET /api/v1/ota`: `status` idle, `auto` off, `repo` "", `message` "Update checks are off in this build…"; `POST /ota` → 409 with that message; `POST /ota/check` → 202, result stays idle. `POST /api/v1/ota/upload` unchanged | QEMU/CI never calls api.github.com; a fork installs by upload until it sets its own repo. A real repo gives the emulator behaviour. |
| Low-memory boot | n/a | No PSRAM: gray planes are not allocated → B/W only; app framebuffer falls back to internal RAM, and if that fails too the UI draws nothing (no crash). Panel init failure and LittleFS format/failure are logged (`!!!` lines) and boot continues; nothing restart-loops | First flash on real hardware; the web console must stay reachable to diagnose. |
| Long-run network health | n/a (simulated Wi-Fi/HA never degrade) | `core/net_policy` + `net/health`: HA reconnect backoff 2 s → 60 s with ±20 % jitter; Wi-Fi with saved credentials offline: `reconnect()` every 15 s, radio reset (`WiFi.mode(OFF)` → STA → `begin`) every 10 min, maintenance restart after 60 min (doubling per consecutive Wi-Fi restart, cap 8 h, count kept in RTC memory); link up but every HA connect / token refresh failing (4 in a row over 5 min, #108): `reconnect()` (QEMU: DHCP client restart), the wait doubling per relink without a success (cap 60 min); TLS (HA https, token refresh, GitHub, firmware download) skipped while the largest free internal block is < 20 KB or internal free < 64 KB (#79), and 30 min below that → restart 03:00–03:59. No restart while an OTA runs or the image is unconfirmed. Wi-Fi power save off during OTA download/upload and HA auth. Nothing new on screen: Wi-Fi stays "Offline", HA "Offline". `GET /api/v1/status` adds `heap_largest_block`, `heap_min_free` (emulator: fixed values) | ROBUSTNESS_PLAN phase 2; device-only failure modes. |
| Large text on narrow tiles | CSS clips/wraps | big values shrink to fit (thermo), long light labels split room/name, chart summary dropped on 1-wide charts | No overflow on e-ink. |
| Glyphs `⇧ ⌫ ▾ ✓` | font glyphs | drawn shapes / synthesised (Atkinson lacks them); `→ ← ✓` fall back to IBM Plex Mono | Font coverage. |
| Fonts | browser rendering of Atkinson Hyperlegible | pre-rendered 2-bit AA bitmaps at the design sizes (12–30 full Latin-1, 34–52 ASCII, 76/92/150 digits) | Flash (390 KB total). |
| Mock data | `PRICES`, `ZONE_LIST`, … | entity conventions in `src/core/entities.h`; missing values render as "—" | Never fake numbers. |
| Where values come from | mock data keyed by logical id | `core/entity_map` maps HA → logical ids: Energy dashboard (`energy/get_prefs`: power sensors from `stat_rate`/`power`/`power_config`, else power/battery sensors on the meters' devices via one `render_template`; today/hourly from `recorder/statistics_during_period`; prices from the grid's `entity_energy_price`, Nord Pool `today`/`raw_today`, Tibber `today`, Frank/EnergyZero `prices`, ENTSO-e `prices_today`), identity (HA entity already named like the logical id), overrides in settings `entities` (`PUT /api/v1/settings {"entities":{"sensor.x4_route_renkum_arn":"sensor.my_bus"}}`, `-` prefix negates). Travel routes and `sensor.living_temperature` are only mapped by override/identity (OPEN_QUESTIONS: no `[LINE]` guess). Battery power: HA + = discharging, UI + = charging (negated). Unmapped → "—" | HA has no fixed entity names. |
| Sign-in callback errors | 400 page (unknown state), `?signin=denied`; a non-admin HA user gets a view-only session (#22) | same (was 302 `?auth_error=…`; fixed under QEMU) | Spec. |
| `GET /diagnostics` boot ring | device-sim: boots only on simulated restart / crash (`__sim/control {crash}`), fixed heap and panel figures | `esp_reset_reason()` at the top of `setup()`; ring in `RTC_NOINIT` (magic ^ struct size + FNV-1a checksum, rejected after power-on or an OTA with another layout), copied to userdata `/diag.json` at boot and every 30 min. Running boot refreshed every 10 s | After a power loss the previous boot's uptime is at most 30 min stale (file copy). Ring logic matches `spec/test-vectors/diag.json`. |
| Panic message | sim: fixed text | `-Wl,--wrap=panic_abort` (abort/assert/`esp_system_abort`) into RTC memory; CPU exceptions skip `panic_abort`, so the core dump's panic reason (`esp_core_dump_get_panic_reason`) fills in | A core dump left over from an older crash could lend its reason to a later crash reset with no message. `DELETE /diagnostics` erases it. |
| `GET /diagnostics/coredump` scope | write | write | The image holds RAM, including access tokens in flight. Not a read-scope endpoint. |
| Panel diag (`panel`) | sim: UC8179 via probe | `freeink::getXteinkDisplayProbeDiag()` + `BoardConfig::ACTIVE.displayController` + read-only `nvs_open("hw_calib")` `screenType`; QEMU: controller `none`, source `none` | The boot log said "(NVS hw_calib)" when no probe ran; NVS never decides on the X4 Pro.
