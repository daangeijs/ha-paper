# Navigation without a flash: fast, clean and full refreshes (issue #197)

| Topic | Design handoff / before | Now (emulator = firmware) | Why |
|---|---|---|---|
| Screen change, home, app switch, page overview open/close, open page, keyboard, Wi-Fi connecting, back to networks | full refresh (SSD1677 `0x22=F7`: 3–4 flashes, ~1.7 s, then the gray pass) | **fast**: whole-frame differential update (`0x22=FC`, no flash, ~0.5 s) with the gray overlay on top; every `kNavClean` = 10th navigation since the last clean is a **clean** instead (`RefreshPolicy::requestNav`, emulator `decideNav`, vectors `refresh.json` `navigation`). A fast counts toward the scheduled clean like a partial | 77 full refreshes in 23 min on the real test unit, and taps felt lost. Stock X4 firmware and CrossPoint turn pages with `FC` and clean every N pages with the single-pass HALF. |
| Every other panel-wide redraw (boot, wake, glance render, standby, night face / night end, peek, setup steps, new config, style, language, OTA screen, scheduled clean, ghosting limit) | full (`F7`) | **clean**: HALF (`0x1A=5A`, `0x22=D7`, one short flash). Rows in other deviation files that say "full refresh" mean this clean now | The OEM firmware's only clean in normal use is the HALF; `F7` is a dead branch there. |
| `POST /display/refresh` | full (`F7`) | still **full** (`F7`), the only caller | Manual deep clean if residue ever survives a HALF. |
| Grays after a fast refresh | (fast refreshes did not exist; partials stay B/W, #38) | gray overlay after the fast base. A pixel gray on the glass is white in both RAM planes (#201 rule), so a plain `FC` would skip it: the gray would stay, or get the overlay twice. Before a fast that follows a gray frame, SSD1677 RED (`0x26`) gets NOT(new base) at the old gray pixels (`core/epd_sequence.h` `redSeedByte`, glass model in `test/test_epd_sequence`), so each takes one full B/W transition. UC8179/UC8279 take a clean there instead. Costs a third 48 KB PSRAM plane | Keeps Sleek's grays on every page without the flash. Untested on hardware. |
| Refresh log lines | `EPD full refresh (<reason>)` | `EPD fast refresh (<reason>)` / `EPD clean refresh (<reason>)`; the hw layer logs `EPD <kind> refresh <ms> ms[ · gray pass][ · red seeded]` | Measurement on the real panel. |
| Counters | `App::Stats` full / partial | `fastRefreshes` added; `fullRefreshes` counts the cleans (so `last_full_refresh` and glance tallies keep their meaning). Device sim `/status` `refreshes.boot` adds `fast` and `clean`; the firmware `/status` fields wait on a change in `net/power.cpp` (outside this issue's files) | — |
